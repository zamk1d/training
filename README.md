# Sport Tracker

Лёгкий self-hosted дневник тренировок, питания и параметров тела. Один процесс, одна SQLite-база, никаких внешних сервисов: данные лежат у тебя.

## Возможности

**Учёт**
- Тренировки: упражнения с повторами по каждому подходу (`12 · 10 · 8`), заметки к тренировке.
- Питание: приёмы пищи с белком и калориями, суммарный белок за день.
- Тело: вес, рост, заметки.
- Шаблоны упражнений и еды: создаются на вкладке «Шаблоны» или кнопкой 💾 прямо в форме дня, редактируются кликом.
- Подсказка «прошлый раз: 12 · 10 · 8 — подставить» под каждым упражнением и кнопка «↺ Как в прошлый раз».

**Аналитика**
- Статистика и графики за выбранный период: 7 / 30 / 90 дней или всё время.
- Объём тренировок, белок по дням с настраиваемой целью (пунктирная линия, «цель выполнена в N из M дней»), динамика веса.
- Прогресс по любому упражнению: лучший подход или суммарные повторы.
- Клик по точке графика открывает соответствующий день.

**Удобство**
- Вкладки «Обзор / Дни / Шаблоны» с прилипающей панелью; список дней сгруппирован по месяцам.
- Светлая и тёмная темы.
- Экспорт и импорт JSON (можно выбрать категории при экспорте).

## Стек

Python 3.11+, FastAPI, SQLAlchemy 2, Pydantic 2, Jinja2, SQLite. Фронтенд без сборки: чистый JS и [Chart.js](https://www.chartjs.org/) с CDN.

## Быстрый старт

```bash
git clone <url-репозитория> sport-tracker
cd sport-tracker

# через uv
uv sync
uv run uvicorn app.main:app --reload

# или через pip
python -m venv .venv && source .venv/bin/activate
pip install "fastapi[standard]" "uvicorn[standard]" sqlalchemy jinja2 python-multipart
uvicorn app.main:app --reload
```

Открой http://127.0.0.1:8000. База `sport_tracker.db` создаётся в текущей директории при первом запуске.

> ⚠️ **В сервисе нет аутентификации.** Он рассчитан на одного пользователя и локальный запуск. Не выставляй его в интернет без reverse-proxy с авторизацией (например, Caddy/nginx + basic auth или VPN).

> Графики грузят Chart.js с CDN (jsDelivr), поэтому для интерфейса нужен интернет. Для полностью офлайн-работы скачай библиотеки в `static/` и поправь `<script>` в `base.html`.

## API

Интерактивная документация: `/docs` (Swagger) и `/redoc`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/days` | Все дни с данными, от новых к старым |
| GET | `/api/day/{YYYY-MM-DD}` | Один день |
| POST | `/api/day/{date}` | Создать или **заменить** день целиком |
| DELETE | `/api/day/{date}` | Удалить день |
| GET | `/api/export?workouts=&food=&body=` | Экспорт выбранных категорий в JSON |
| POST | `/api/import/json` | Импорт (существующие дни пропускаются) |
| GET/POST/DELETE | `/api/templates/exercises`, `/api/templates/meals` | Шаблоны (POST — upsert по имени) |
| GET | `/api/chart/{workouts,protein,weight}` | Готовые ряды для графиков |

`POST /api/day/{date}` атомарный: если запись не удалась, предыдущее состояние дня сохраняется.

### Формат JSON для импорта

```json
{
  "days": [
    {
      "date": "2026-01-15",
      "workout_notes": "Тяжело, но сделал",
      "exercises": [
        { "exercise_name": "Классические отжимания", "reps_list": [12, 10, 8] },
        { "exercise_name": "Подтягивания", "sets": 3, "reps": 6 }
      ],
      "meals": [
        { "date": "2026-01-15", "description": "Омлет из 3 яиц", "protein_g": 20, "calories": 280 }
      ],
      "body": { "date": "2026-01-15", "weight_kg": 67.2, "height_cm": 176 }
    }
  ]
}
```

Любой блок можно опустить. Формат `sets` + `reps` поддерживается для старых данных. Файл из `/api/export` можно импортировать обратно.

## Данные и бэкапы

Вся информация в одном файле `sport_tracker.db`. Для бэкапа достаточно скопировать его (лучше при остановленном сервисе) или регулярно делать экспорт в JSON.
